Install guide · Windows PC + Android phone

Setting up LocalHBT
on your own machine

A Hebrew–English interlinear translator that runs entirely on your own computer. The phone app is a window onto it, reached over a private Tailscale link that never touches the public internet. Work through this once and it stays set up.

The one-line version

The computer does all the work. The phone is only a screen. The single thing you have to configure is telling the phone your computer's Tailscale address.

Your phone LocalHBT app — just a viewer
→
Tailscale Private encrypted link between your two devices
→
Your computer Server on port 8770 + Ollama running the model

Nothing is hosted by anyone else. If the computer is asleep or the server is closed, the phone shows nothing — there is no cloud copy to fall back on.

Before you start

Reality check

The translation model is 24 billion parameters. The included Modelfile trims its context window to 16K specifically so the weights and cache fit in about 20 GB of video memory.

Check this first

On a machine with a large dedicated GPU, a page translates in minutes. On a laptop with integrated graphics, Ollama falls back to the CPU and the same page can take hours. Everything else here will install perfectly well — it will just be too slow to use. Confirm the hardware before spending time on the rest.

Part one: the computer

Do these in order

Each step depends on the one before it. Finish this part and confirm the translator works in a browser on the computer itself before you touch the phone.

01

Install Tailscale and sign in

Download it from tailscale.com, install, and sign in with whichever account you like — Google, Microsoft, GitHub. This computer now belongs to your private network.

Use the same account on the phone later. That is what puts the two devices on the same network and lets them see each other.

02

Install Python and Ollama

Python from python.org — tick “Add python.exe to PATH” on the first screen of the installer. Ollama from ollama.com; it starts with Windows and stays running in the background.

03

Build the translation model

Open a terminal inside the project folder and run:

ollama create dictalm-fast -f Modelfile

This pulls roughly 14 GB the first time, so give it a while. The name dictalm-fast matters — the server looks for exactly that. If it ever goes missing, run the same line again.

04

Start the translator

Double-click Run Translator.bat. A console window opens and stays open — that window is the server, so leave it be. A browser tab opens on the interface.

Translate something small here before going further. If it does not work on the computer, the phone cannot fix it.

05

Write down the computer's Tailscale address

In another terminal:

tailscale ip -4

It prints one line beginning with 100. — something like 100.104.64.110. That is this computer's permanent address on your private network. It does not change when you move house or switch WiFi.

The address you will type into the phone is that number with the port on the end:

http://100.x.y.z:8770

Part two: the phone

Android

The app is a shell around the same interface the computer shows. It needs no rebuild and no developer tools — you are installing the file as it ships.

06

Install Tailscale on the phone

From the Play Store. Sign in with the same account you used in step 1, and switch the connection on. The phone gets its own 100. address, which you will never need to type anywhere.

07

Copy across and install the app

Take Android\build\LocalHBT.apk from the project folder to the phone by whatever route suits — USB cable, Drive, email to yourself. Open it on the phone.

Android will object that the file did not come from the Play Store; approve “install unknown apps” for whichever app you opened it with, then install. Look for LocalHBT in the app drawer.

08

Type your computer's address on first launch

The app opens asking “Where is the translator?” with an address already filled in. Replace it with the address from step 5, then tap Connect.

Do not tap “Use default”

The pre-filled address belongs to the machine this app was originally built on. It means nothing on your network, and the app will simply fail to load with no useful explanation. Clear the box and type your own address.

It is remembered from then on. If the address ever changes, the ⚙ button in the app's header brings this dialog back.

Part three: using it

Every time from now on

Setting up happens once. This is the whole routine afterwards, and it is the same on the computer and the phone: start the server, then open a window onto it.

A

Start the server on the computer

Double-click Run Translator.bat. Two things happen: a black console window opens, and your browser opens the translator.

The console window is the program

It looks like a leftover, but closing it stops the translator. Minimise it and leave it alone. Nothing works — on the computer or the phone — while it is closed.

Nothing else needs starting. Ollama is already running in the background, and Tailscale reconnects itself when the machine wakes.

B

Use it on the computer

The browser tab that opened is the translator. If you close it by accident, open a new one at:

http://127.0.0.1:8770

Use that address on the computer running the server — not its Tailscale address. It works whether or not Tailscale is connected, because it never leaves the machine.

C

Use it on the phone

Check Tailscale is connected, then open LocalHBT. It remembers the address from setup and opens on your documents, so there is nothing to type again.

The phone and the computer can both be open at once. They are two windows onto the same server, not two copies — a translation started on one is visible on the other.

D

Leave it running, or stop it

Long translations run for hours, so the usual thing is to leave the console window open and let it work. The computer must stay awake for that — translation happens in Ollama on the PC, and a sleeping machine stops mid-sentence.

To stop: close the console window. A translation in progress is not lost. Progress is saved after every chunk, and pressing Translate next time picks up from where it stopped.

The part people get wrong

Worth reading once
It is the computer's address, never the phone's

The phone has its own Tailscale address, and it is irrelevant here. The phone is the one doing the asking; the computer is the one being found. Nothing you type into the app is ever the phone's own number.

Ordinary WiFi will not work, on purpose. The server answers only itself and the Tailscale address range. Putting both devices on the same home or café WiFi and using the computer's normal 192.168.x.x address gets you nothing. Tailscale is not an optional convenience here — it is the only way in, which is also why the port is safe to leave open.

Windows Firewall needs nothing done to it. Tailscale's adapter counts as a Private network, and Python is already allowed inbound there. If you find yourself disabling the firewall, something else is wrong.

The computer must be awake. Translation happens in Ollama on the PC. A sleeping computer means a blank app, so it is worth setting the machine never to sleep if you plan to read on the phone while it works.

When it does not work

Troubleshooting
Symptom → cause
What you seeWhat it usually means
App cannot reach the computer The console window was closed, the PC is asleep, or Tailscale is disconnected on one of the two devices. Check all three in that order.
App loads, but says the address is wrong You kept the pre-filled address. Tap ⚙ and enter your own from step 5.
“Cannot reach Ollama” Ollama is not running. Start it, then reload the page.
Model not found Re-run ollama create dictalm-fast -f Modelfile in the project folder.
“LocalHBT is ALREADY RUNNING” A server is already up. Close every LocalHBT console window and start one again — two copies sharing the port cause confusing, half-broken behaviour.
Translation is unbearably slow It is running on the CPU rather than the GPU. See the reality check at the top; this is a hardware limit, not a setting.

Changing things later

Optional

The interface lives in index.html on the computer, not inside the app. Edit it and the phone picks it up on the next reload — the APK never needs rebuilding for an interface change. Editing server.py is the exception: that one needs the console window closed and reopened.

Everything here runs on hardware you own. No account, no subscription, and no text leaves your machine — which is the entire reason it is built this way.
